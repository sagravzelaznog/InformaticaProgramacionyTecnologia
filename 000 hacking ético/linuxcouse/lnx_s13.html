Laboratorio 13: Cuarentena y Adquisición Quirúrgica

Bienvenido al nivel pericial. Has incautado un USB sospechoso. La regla de oro del análisis forense es: Nunca se trabaja sobre la evidencia original. Hoy aprenderemos a identificar el dispositivo físico, montarlo en cuarentena (solo lectura) y crear un clon exacto bit a bit usando tu Sandbox de Kali Linux.

Paso 1: El Mapa del Territorio (lsblk y fdisk)

En Linux, los discos duros y USBs no son "C:" o "D:". Son dispositivos de bloque en la carpeta /dev/ (ej. sda, sdb, nvme0n1). Antes de clonar, debes estar 100% seguro de cuál es tu disco (el sistema) y cuál es la evidencia.

# Listar dispositivos de bloque (fácil de leer por el tamaño)
-(kali㉿kali)-[~]$ lsblk

# Ver particiones y sistemas de archivos con detalle forense
-(kali㉿kali)-[~]$ sudo fdisk -l

Paso 2: La Sala Blanca (Montaje Solo Lectura)

Si el sistema operativo monta el USB automáticamente, podría alterar los metadatos de "último acceso". Como forenses, intervenimos manualmente para montarlo como Read-Only (ro).

# 1. Creamos la "mesa de disección" (el punto de montaje)
-(kali㉿kali)-[~]$ sudo mkdir -p /mnt/evidencia_cuarentena

# 2. Montamos la partición (suponiendo que es sdb1) en modo estricto
-(kali㉿kali)-[~]$ sudo mount -o ro /dev/sdb1 /mnt/evidencia_cuarentena

Paso 3: Simulador "Disk Destroyer" (Lógica dd)

El comando dd es ciego y obediente. Copia de if (Input File) hacia of (Output File). Si inviertes estos dos parámetros, escribirás un archivo vacío sobre el USB sospechoso, destruyendo la evidencia para siempre. Practica la lógica en este simulador antes de avanzar.

➡️

Paso 4: El Clonador Universal (dd real)

Ahora que tu mente entiende el flujo de datos, ejecutaremos el comando. dd creará una imagen bit a bit (.img o .dd). Esta imagen incluirá incluso los archivos "borrados" que residen en el espacio libre del USB.

Paciencia Forense: `dd` no muestra barra de progreso por defecto. Añadir `status=progress` es vital para no pensar que la terminal se ha congelado durante copias de cientos de Gigabytes. 
# Clonamos el disco completo (sdb), no solo la partición (sdb1)
# bs=4M acelera la copia usando bloques de memoria más grandes
-(kali㉿kali)-[~]$ sudo dd if=/dev/sdb of=/home/kali/Desktop/evidencia_clon.img bs=4M status=progress
