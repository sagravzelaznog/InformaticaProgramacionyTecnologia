Misión 05: El Muro Infranqueable

Situación: Tienes la evidencia en tus manos. Sin embargo, los sistemas operativos modernos son "ruidosos". Al conectar un disco, intentan montar el sistema de archivos automáticamente, actualizando metadatos, fechas de último acceso y creando archivos temporales.

Tu misión es levantar un muro. Antes de interactuar con cualquier disco de evidencia, debes configurar bloqueadores de escritura por software e implementar un montaje estricto de solo lectura (Read-Only). Hoy validarás que tu barrera sea impenetrable.

Laboratorio Hands-On: Bloqueo de Escritura en Kali Linux

Abre tu máquina virtual. Ejecuta la siguiente escalada de comandos para montar una unidad y comprobar la inmutabilidad de los datos.

1. Implementar Bloqueadores de Escritura (Software)

Configura el entorno de Kali Linux para desactivar el auto-montaje y preparar el sistema para manejar evidencia digital de manera segura.

# Verificar discos conectados sin montarlos
sudo fdisk -l

# Instalar/Verificar utilidades de bloqueo forense (si aplica)
sudo apt-get install disktype -y

2. Montar Disco en Modo 'Read-Only'

Montaremos la partición de evidencia utilizando el flag -o ro (Read-Only) y loop (si es una imagen), asegurando que el kernel bloquee cualquier instrucción de escritura.

# Crear punto de montaje estéril
sudo mkdir -p /mnt/evidencia_segura

# Montar en estricto Solo Lectura (reemplaza sdX1 por tu partición)
sudo mount -o ro /dev/sdX1 /mnt/evidencia_segura

# Verificar los permisos de montaje actuales
mount | grep evidencia_segura

3. Test de Intrusión: Intentar Escribir en el Disco

La confianza es buena, pero el control es mejor. Intenta forzar la escritura de un archivo en el disco montado para verificar que el bloqueo forense funciona.

# Intentar crear un archivo de texto en la evidencia
sudo touch /mnt/evidencia_segura/prueba_contaminacion.txt

# El sistema DEBE arrojar el error: "Read-only file system"
# Desmontar al finalizar
sudo umount /mnt/evidencia_segura

¡Barrera Forense Establecida!

Has comprobado empíricamente que tu entorno no alterará la evidencia. El error "Read-only file system" es la confirmación visual de que tu procedimiento cumple con el rigor legal y técnico de la Cadena de Custodia.
