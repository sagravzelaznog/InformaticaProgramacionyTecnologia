🏗️ Sesión 5: HTML Semántico

Estructurando el Contenido con Significado

Objetivo de la Sesión

Entender y aplicar los elementos semánticos de HTML5 para crear documentos web mejor estructurados, accesibles y fáciles de mantener.

¿Qué es el HTML Semántico?

El HTML semántico utiliza etiquetas que dan significado al contenido, más allá de solo definir su apariencia. Esto ayuda a:

  • Mejorar la accesibilidad para usuarios con discapacidades
  • Optimizar el SEO (posicionamiento en buscadores)
  • Facilitar el mantenimiento del código
  • Mejorar la compatibilidad con diferentes dispositivos

Elementos Semánticos Principales

<header>

Representa el encabezado de una sección o documento. Puede contener elementos de encabezado, logotipos, formularios de búsqueda, etc.

<header>
    <h1>Título del Sitio</h1>
    <p>Lema o descripción corta</p>
</header>

<nav>

Contiene enlaces de navegación principales. No todos los grupos de enlaces necesitan estar en un <nav>, solo los bloques principales de navegación.

<nav>
    <ul>
        <li><a href="inicio.html">Inicio</a></li>
        <li><a href="servicios.html">Servicios</a></li>
        <li><a href="contacto.html">Contacto</a></li>
    </ul>
</nav>

<main>

Representa el contenido principal del documento. Debe haber solo un <main> por documento y no debe estar dentro de <article>, <aside>, <footer>, <header>, o <nav>.

<main>
    <h1>Artículo Principal</h1>
    <p>Contenido principal de la página...</p>
</main>

<article>

Representa una composición auto-contenida que podría distribuirse o reutilizarse independientemente, como una entrada de blog, un artículo de periódico, un comentario, etc.

<article>
    
Título del Artículo

    
Contenido del artículo...

    
Publicado el 21 de enero de 2026

</article>

<section>

Representa una sección genérica de un documento, típicamente con un encabezado. Usa <article> cuando el contenido sea auto-contenido.

<section>
    
Nuestros Servicios

    
Conoce todo lo que ofrecemos...

</section>

<aside>

Representa contenido que está indirectamente relacionado con el contenido principal, como barras laterales, publicidad, biografías del autor, etc.

<aside>
    
Sobre el Autor

    
Biografía corta del autor...

</aside>

<footer>

Representa el pie de página de una sección o documento. Normalmente contiene información sobre el autor, enlaces relacionados, derechos de autor, etc.

<footer>
    
© 2026 Mi Sitio Web. Todos los derechos reservados.

    

        Política de privacidad | 
        Términos de uso
    

</footer>

Código HTML del Ejemplo:

<body>
    <header>
        <h1>Mi Sitio Web</h1>
        <nav>
            <ul>
                <li><a href="#">Inicio</a></li>
                <li><a href="#">Blog</a></li>
                <li><a href="#">Contacto</a></li>
            </ul>
        </nav>
    </header>
    
    <main>
        <article>
            <h2>Artículo Principal</h2>
            <p>Contenido principal del artículo...</p>
            <section>
                <h3>Sección del Artículo</h3>
                <p>Más detalles sobre el tema...</p>
            </section>
        </article>
        
        <aside>
            <h3>Artículos Relacionados</h3>
            <ul>
                <li><a href="#">Tema relacionado 1</a></li>
                <li><a href="#">Tema relacionado 2</a></li>
            </ul>
        </aside>
    </main>
    
    <footer>
        <p>© 2026 Mi Sitio Web</p>
    </footer>
</body>

Semántico vs No Semántico

❌ Código No Semántico

<div id="header">
    <div class="nav">
        <div class="menu">Inicio</div>
        <div class="menu">Blog</div>
    </div>
</div>

<div class="main">
    <div class="post">
        <div class="post-title">Título</div>
        <div class="post-content">Contenido...</div>
    </div>
</div>

<div id="footer">Pie de página</div>

Problemas:

  • Difícil de entender el propósito de cada sección
  • Peor accesibilidad para lectores de pantalla
  • Más difícil de mantener
  • Peor SEO

✅ Código Semántico

<header>
    <nav>
        <ul>
            <li><a href="#">Inicio</a></li>
            <li><a href="#">Blog</a></li>
        </ul>
    </nav>
</header>

<main>
    <article>
        <h1>Título</h1>
        <p>Contenido...</p>
    </article>
</main>

<footer>Pie de página</footer>

Ventajas:

  • Estructura clara y comprensible
  • Mejor accesibilidad
  • Más fácil de mantener
  • Mejor SEO

Ejemplo Práctico: Blog Semántico

Vamos a transformar un blog simple en uno semántico:

Instrucciones:

  1. Crea una carpeta llamada blog-semantico
  2. Crea un archivo index.html con la estructura básica
  3. Implementa la siguiente estructura semántica:
    • Un <header> con el título del blog
    • Una <nav> con enlaces a categorías
    • Un <main> que contenga varios <article>
    • Cada artículo debe tener un <header>, <section> y <footer>
    • Un <aside> con información del autor
    • Un <footer> con información de derechos de autor

Actividad Práctica

Refactoriza una página web existente (o crea una nueva) siguiendo estos pasos:

Requisitos:

  1. Identifica y reemplaza los <div> genéricos por elementos semánticos apropiados
  2. Asegúrate de que la estructura de encabezados sea lógica (solo un <h1> por página)
  3. Agrupa el contenido relacionado con <section>
  4. Usa <article> para contenido independiente
  5. Incluye una barra lateral con <aside>
  6. Agrega un pie de página semántico
  7. Verifica la accesibilidad con un validador

💡 Consejo:

Usa la herramienta de desarrollo de tu navegador para inspeccionar la estructura de la página y asegurarte de que los elementos semánticos estén siendo utilizados correctamente.

Resumen de la Sesión

  • El HTML semántico usa elementos que describen su significado de manera clara tanto para el navegador como para el desarrollador
  • Elementos estructurales clave: <header>, <nav>, <main>, <article>, <section>, <aside>, y <footer>
  • Beneficios: mejor accesibilidad, SEO, mantenibilidad y legibilidad del código
  • Evita el uso excesivo de <div> cuando exista un elemento semántico más apropiado
  • La estructura semántica debe reflejar la jerarquía y relación del contenido
