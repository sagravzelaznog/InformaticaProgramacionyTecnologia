Sesión 4: Ignorar y Limpiar Archivos

← Volver al Temario Principal

En proyectos de software, es común tener recursos temporales (como archivos de caché o código compilado) o archivos con información secreta (contraseñas o credenciales) que no deben ser compartidos. Puedes hacer que Git ignore estos archivos creando uno o varios archivos .gitignore [1].

Reglas para Subdirectorios

Existen dos formas principales de ignorar archivos que se encuentran dentro de subdirectorios [2]:

  • Desde la raíz: Puedes colocar una ruta absoluta dentro del .gitignore principal. Por ejemplo:
    src/output.log [3].
  • Múltiples archivos .gitignore: Puedes crear un archivo .gitignore directamente en el subdirectorio (ej. dentro de src/) y escribir la ruta relativa:
    output.log [3].

El archivo `.gitignore` Global

Si deseas que ciertas reglas se apliquen a todos los repositorios en tu máquina (muy útil para ignorar archivos del sistema operativo como .DS_Store en Mac o Thumbs.db en Windows), puedes configurar un .gitignore global [4, 5]:

git config --global core.excludesfile <Ruta_Al_Archivo_Global>

Recuerda que si el .gitignore local incluye explícitamente un archivo, este tendrá prioridad sobre el global [6].

En ocasiones necesitas mantener un archivo dentro del repositorio de Git pero deseas ignorar cualquier cambio posterior que le hagas localmente. Esto es muy útil para archivos de configuración que proporcionan valores por defecto y requieren sobreescrituras locales [7, 8].

Uso de `assume-unchanged`

Puedes indicarle a Git que "asuma" que un archivo no ha sido modificado y que deje de revisar o reportar sus cambios usando el siguiente comando [8]:

git update-index --assume-unchanged mi-archivo.txt

Al hacer esto, Git forzará la omisión de cualquier cambio en el archivo. Sin embargo, ten cuidado: si decides hacer un "pull" de este archivo o lo guardas en el "stash", tus cambios locales ignorados se perderán [9].

Revertir el estado

Si necesitas que Git vuelva a "prestar atención" a las modificaciones de este archivo, puedes revertir la configuración ejecutando [9]:

git update-index --no-assume-unchanged mi-archivo.txt

El comando git clean es útil cuando tienes archivos no rastreados (untracked) en tu directorio de trabajo y deseas deshacerte de ellos de manera rápida.

Previsualización con `--dry-run` (`-n`)

Antes de eliminar algo de forma permanente, es una excelente práctica usar la bandera -n (o --dry-run). Esto no borrará nada, sino que solo mostrará una lista de los archivos que serían eliminados [10]:

git clean -n

Eliminar archivos y directorios no rastreados (`-f` y `-d`)

  • Eliminación forzada: Para eliminar definitivamente todos los archivos no rastreados en tu directorio, utiliza [11]:
    git clean -f
  • Eliminar directorios: Si también tienes carpetas completas que no están siendo rastreadas y quieres borrarlas junto con su contenido, agrega la bandera -d [12, 13]:
    git clean -fd

Nota: Por defecto, Git se negará a eliminar archivos o directorios a menos que se le pase la bandera de fuerza -f, -n o interactiva -i [10].
