Inicializar un repositorio (git init)

Una vez que tienes Git instalado, navega al directorio que deseas poner bajo control de versiones y crea un repositorio vacío utilizando el comando git init [1]. Esto crea una carpeta oculta llamada .git, la cual contiene todas las herramientas (plumbing) necesarias para que Git funcione [1].

Clonar un repositorio existente (git clone)

El comando git clone se utiliza para copiar un repositorio existente desde un servidor (como GitHub o BitBucket) a tu máquina local [2]. Esto crea un directorio con el código fuente del proyecto y una subcarpeta .git que contiene el historial completo [3].

# Clona el repositorio remoto a un directorio local
    # Reemplaza 'username' y 'projectname' por los tuyos
    git clone https://github.com/username/projectname.git

    # Si el repositorio es muy grande, descarga solo el último commit (shallow clone):
    git clone https://github.com/username/projectname.git --depth 1
 
    # Para clonar una rama específica:
    git clone --branch nombre-rama https://github.com/username/projectname.git

Clonación Profunda vs Superficial

  • Clonación profunda (Regular Clone): Al ejecutar git clone <url> descargas el repositorio entero, incluyendo el historial completo y todas sus ramas [4].
  • Clonación superficial (Shallow Clone): Clonar un repositorio gigantesco con años de historial puede tardar demasiado. Para evitar esto, puedes agregar el parámetro --depth 1 para descargar solo el último commit [5].

    git clone [repo_url] --depth 1 [5].

Debes establecer quién eres antes de crear cualquier commit para asegurarte de que lleven asociados el nombre de autor y el correo electrónico correctos [6].

Configuración Global

Para declarar tu identidad en todos tus repositorios de la máquina, utiliza la bandera --global. Esto almacena la configuración en tu archivo de usuario ~/.gitconfig [7]:

# Establece tu nombre global (aplica a todos los repositorios en esta máquina)
            # Útil para identificar al autor en los commits
            git config --global user.name "Tu Nombre"

            # Establece el correo asociado a tus commits
            git config --global user.email tu.correo@ejemplo.com

            # Verifica la configuración actual
            git config --list

Configuración Local (Por Repositorio)

Si trabajas con múltiples identidades (por ejemplo, una cuenta de trabajo y una personal de código abierto), puedes definir la identidad dentro de un repositorio específico omitiendo --global. Esta información se guardará en .git/config y tendrá prioridad sobre la configuración global cuando trabajes en ese proyecto en particular [7, 8]:

# Entra en la carpeta del proyecto y configura identidad solo para este repo
        cd /ruta/a/mi/repo

        # Sobrescribe la identidad global para este repositorio
        git config user.name "Tu Nombre de Trabajo"
        git config user.email correo_de_trabajo@ejemplo.com

        # Comprueba la configuración local
        git config --local --list

Git te permite crear atajos, conocidos como "alias", para mejorar tu productividad y evitar escribir comandos largos repetidamente.

Alias Básicos

Puedes crear un alias a través de la línea de comandos. Por ejemplo, para hacer un commit escribiendo solo git ci en lugar de git commit [9, 10]:

Comentario: los alias te permiten ahorrar tiempo y estandarizar comandos frecuentes. Se almacenan en tu archivo de configuración global y pueden exportarse si lo necesitas.

git config --global alias.ci "commit"
git config --global alias.st "status"
git config --global alias.co "checkout"

Alias Avanzados

Git permite usar comandos que no son de git y utilizar la sintaxis completa de la shell de comandos si agregas el prefijo ! antes de ellos [11]. Esto es útil para construir funciones de script más complejas. Por ejemplo, un alias para agregar rápidamente una regla a tu archivo .gitignore desde la raíz de tu proyecto [11, 12]:

Comentario: los alias que invocan la shell pueden ser poderosos pero peligrosos; evita introducir entradas no validadas.

git config --global alias.ignore "! echo $1 >> .gitignore"

Así, ejecutando git ignore .tmp/, Git añadirá la regla al archivo automáticamente [12].
