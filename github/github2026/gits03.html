Sesión 3: Exploración del Historial y Diferencias

← Volver al Temario Principal

El comando git log es tu herramienta principal para revisar qué ha sucedido en el repositorio. Por defecto, lista los commits en orden cronológico inverso, mostrando su hash (SHA-1), autor, fecha y mensaje [1].

Formateos personalizados (--oneline y --graph)

  • Formato compacto: Si el historial es extenso, la bandera --oneline imprime cada commit en una sola línea, lo que facilita visualizar muchos commits a la vez [2].
  • Grafo de ramas: Para ver cómo las ramas se dividen y fusionan en una estructura gráfica y atractiva, puedes combinar comandos [3]: 
    git log --decorate --oneline --graph

Búsqueda de cadenas en el historial

Si necesitas encontrar cuándo se hizo un cambio que menciona cierta palabra clave en su mensaje, puedes usar la bandera --grep [4].

git log --all --grep "texto a buscar"

También puedes buscar cuándo se añadió o eliminó una línea específica en el código fuente usando git log -S"cadena" o expresiones regulares con -G [5].

Para generar métricas o listar qué miembros del equipo han participado en el proyecto, git shortlog agrupa los commits por autor en orden alfabético [6].

Banderas útiles de estadísticas

  • Sumario (-s o --summary): Oculta las descripciones de los commits individuales y muestra simplemente el número total de commits al lado del nombre de cada autor [6].
  • Ordenado por número (-n o --numbered): Cambia el ordenamiento predeterminado (alfabético) para ordenar la lista descendentemente según la cantidad de contribuciones hechas [7].
git shortlog -sn

Esto te entregará rápidamente un listado de los principales colaboradores organizados por la mayor cantidad de trabajo aportado.

Mientras que el historial muestra cambios ya guardados, git diff te permite comparar diferentes estados de tu proyecto antes o después de crear un commit.

Directorio de trabajo actual

Al ejecutar git diff sin parámetros, Git mostrará las diferencias entre el último commit y los cambios locales que aún no están preparados (unstaged) en tu directorio de trabajo [8].

Área de Preparación (--staged)

Si ya agregaste los archivos con git add, una ejecución simple de git diff no arrojará resultados. Para ver las diferencias de los archivos que ya están en el área de preparación (y que formarán el próximo commit), debes ejecutar [9, 10]:

git diff --staged

(Nota: git diff --cached funciona exactamente igual como un sinónimo [10]).

Comparar entre ramas

Si quieres ver en qué difieren dos ramas antes de fusionarlas, puedes especificar sus nombres. Esto mostrará las diferencias desde que la nueva rama divergió de la original [10]:

git diff rama_original rama_nueva

O de manera equivalente: git diff original..nueva.
