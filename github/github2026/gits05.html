Sesión 5: Ramas (Branching) y Fusiones (Merging)

← Volver al Temario Principal

Una rama en Git es un entorno independiente donde puedes desarrollar nuevas características sin afectar la línea principal del código. Fundamentalmente, una rama es simplemente un puntero a un commit [1].

Crear y cambiar de ramas

  • Crear una rama nueva: Estando en tu rama actual, usa git branch <nombre> para crearla [2].
  • Cambiar a otra rama: Utiliza el comando git checkout <nombre> para moverte a una rama existente [2, 3].
  • Atajo (crear y cambiar): Si deseas hacer ambas cosas en un solo paso, usa la bandera -b con checkout [3]: 
    git checkout -b <nombre>

Listar ramas

Para visualizar todas las ramas disponibles en tu repositorio (tanto locales como las que rastrean remotos), puedes usar la bandera -a o --all [4, 5]:

git branch -a

Git marcará con un asterisco (*) la rama en la que te encuentras actualmente [5].

Conforme avanza el desarrollo, necesitarás organizar y limpiar las ramas que ya no necesitas.

Renombrar (Mover) Ramas

Puedes renombrar la rama en la que te encuentras actualmente usando el comando de mover (-m o --move) [4, 6]:

git branch -m nuevo_nombre

Si deseas renombrar una rama diferente a la actual, debes especificar el nombre antiguo primero: git branch -m nombre_antiguo nuevo_nombre [6].

Eliminación de Ramas

  • Eliminación Segura (-d): Eliminará la rama localmente, pero fallará de forma segura si la rama contiene cambios que no se han fusionado en otra rama [4, 7, 8].
    git branch -d <nombre_rama>
  • Eliminación Forzada (-D): Si estás completamente seguro de que quieres eliminar una rama (por ejemplo, un experimento fallido), usa la D mayúscula. Esto ignorará las advertencias y eliminará la rama, causando la pérdida de commits no fusionados [4, 7, 9].
    git branch -D <nombre_rama>

Fusionar (merge) es el proceso de integrar el trabajo realizado en una rama dentro de otra [10].

Unir ramas (`git merge`)

Para fusionar una rama en tu rama actual (por ejemplo, en master), primero asegúrate de estar en la rama de destino y ejecuta [10]:

git merge rama_entrante

Fast-forward frente a `--no-ff`

Cuando la rama destino no ha divergido, Git hace un "fast-forward" (moviendo el puntero hacia adelante) sin crear un commit de fusión [11]. Sin embargo, si deseas preservar explícitamente el historial de que existió una rama de característica, puedes forzar un commit de fusión con la bandera --no-ff [11, 12]:

git merge rama_entrante --no-ff -m "Mensaje de fusión"

Resolución manual de conflictos

En ocasiones, Git no puede fusionar automáticamente porque las mismas partes de un archivo se cambiaron en ambas ramas. Te notificará de un "merge conflict" y dejará el archivo en estado "unmerged" [13].

Dentro del archivo afectado, Git añadirá marcadores de conflicto [14]:

<<<<<<< HEAD: archivo.html
Cambios en tu rama actual
=======
Cambios en la rama entrante
>>>>>>> rama_entrante: archivo.html

Para resolverlo debes editar manualmente el archivo eliminando los marcadores (<<<<<<<, =======, >>>>>>>) y decidiendo qué código se queda. Una vez finalizado, marca el conflicto como resuelto utilizando git add <archivo> y luego usa git commit para concluir la fusión [13, 14].
