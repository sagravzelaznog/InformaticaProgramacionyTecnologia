Sesión 6: Trabajo con Remotos, Push y Pull

← Volver al Temario Principal

Trabajar con remotos te permite colaborar compartiendo tu código en servidores centralizados.

Listar Remotos (git remote -v)

Para ver todos los remotos configurados junto con sus URLs para subir (push) y descargar (fetch), utiliza la bandera --verbose o su versión corta -v [1].

git remote -v

Añadir Remotos (git remote add)

Puedes vincular tu repositorio local a uno nuevo en un servidor (como GitHub o BitBucket) usando el comando git remote add <nombre> <url> [2]. Es una convención común nombrar origin al repositorio principal.

Cambiar URLs de Remotos (git remote set-url)

Si el repositorio remoto se ha migrado a otro servidor o necesitas cambiar el protocolo (por ejemplo, de HTTPS a SSH), puedes reasignar su URL de la siguiente manera [3, 4]:

git remote set-url origin https://github.com/usuario/nuevo-repo.git

La sincronización descarga los cambios de un servidor remoto hacia tu máquina local [5].

Fetch vs Pull

  • git fetch: Descarga los objetos y actualiza las referencias del remoto (ej. origin) de manera segura, pero sin integrarlos todavía en tu rama de trabajo actual [6].
  • git pull: Combina internamente dos comandos: un git fetch seguido inmediatamente por un git merge [7]. Descarga los cambios y los fusiona de forma automática en tu rama actual [8].

Mantener un historial lineal con `--rebase`

Si tienes cambios locales en tu rama y descargas commits nuevos del repositorio remoto, git pull creará un commit de fusión de forma automática [9]. Si prefieres evitar este commit de fusión adicional y mantener un historial lineal, puedes decirle a Git que realice un rebase sobre la versión remota [9]:

git pull --rebase nombre-remoto nombre-rama

Esto tomará tus cambios locales y los aplicará encima de los commits que acabas de descargar del remoto [7].

Una vez que has hecho tus commits, el comando git push transfiere esos cambios locales al servidor del repositorio remoto para hacerlos disponibles a los demás colaboradores [10].

Enviar ramas locales

El formato general para enviar tu rama local a un remoto es [10, 11]:

git push <nombre_remoto> <nombre_rama>

Si es la primera vez que envías la rama, debes establecer el rastreo utilizando el atajo -u (o --set-upstream) [12, 13]:
git push -u origin master.

Eliminar ramas remotas

Para borrar una rama que reside en el servidor remoto, puedes usar la bandera --delete o poner dos puntos `:` antes del nombre de la rama [3, 14]:

git push origin --delete nombre_rama

Forzar la subida de cambios (`--force`)

Si reescribes el historial localmente (por ejemplo, con un rebase interactivo), Git rechazará el push regular para proteger el repositorio [15]. Para sobreescribir la historia remota debes usar una subida forzada [16]:

git push -f
⚠️ Atención: Usar git push --force o -f sobreescribe los cambios del remoto para que coincidan con tu copia local. Esto puede provocar que el repositorio remoto pierda commits [17, 18]. Es fuertemente desaconsejado hacerlo en ramas públicas que se comparten con otros colaboradores, ya que desincronizará sus historias de trabajo [18].
