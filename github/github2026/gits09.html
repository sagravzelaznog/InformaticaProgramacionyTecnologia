Cuando estás a la mitad de un trabajo y necesitas cambiar de rama para resolver un problema rápido, no es necesario hacer un commit de código incompleto ni perder tus cambios. Para esto existe el comando git stash [1].

Guardar cambios (git stash)

El comando git stash guarda el estado actual de tu directorio de trabajo y tu área de preparación (índice) en una pila de cambios inconclusos [2]. Al ejecutarlo, tu directorio quedará limpio y listo para cambiar de rama de forma segura [3].

Listar guardados (git stash list)

Puedes ver todos los "stashes" que tienes almacenados usando git stash list [4]. Esto listará los guardados en orden cronológico inverso, identificándolos con nombres como stash@{0} (el más reciente), stash@{1}, etc [4, 5].

Restaurar cambios (pop y apply)

  • git stash pop: Elimina un estado guardado de la lista de stashes y lo aplica encima del estado actual de tu árbol de trabajo [5].
  • git stash apply: Hace exactamente lo mismo que pop, con la diferencia de que no elimina el estado de la lista [5]. Es muy útil si deseas aplicar los mismos cambios temporalmente en varias ramas [6].

Git te permite ser sumamente preciso sobre qué quieres enviar a la pila de "stash".

Mantener el área de preparación (--keep-index)

Si deseas guardar (stash) tus modificaciones, pero dejar el área de preparación (los archivos que ya agregaste con git add) exactamente como está, puedes utilizar la bandera --keep-index [7, 8].

git stash --keep-index

Stash interactivo o parcial (-p)

Si deseas almacenar solo algunas diferencias de tu directorio de trabajo de forma interactiva, puedes usar git stash -p (o --patch) [4, 8]. Git te preguntará iterativamente qué fragmentos (hunks) te gustaría enviar al stash y cuáles te gustaría mantener en tu directorio de trabajo [8, 9].

Incluir archivos no rastreados

Por defecto, git stash no guarda los archivos nuevos que aún no están siendo rastreados por Git. Si necesitas guardarlos también, puedes usar la bandera -u o --include-untracked [7, 8].

A veces no deseas fusionar (merge) toda una rama, sino copiar los cambios de un commit específico de una rama a otra.

Cómo hacer un Cherry-Pick

La herramienta git cherry-pick toma el parche (las diferencias introducidas) de un commit y trata de reaplicarlo en la rama en la que te encuentras actualmente [10]. El comando básico es:

git cherry-pick <commit-hash>

Esto aplicará las modificaciones de dicho commit a tu rama actual, registrando un nuevo commit con el mismo mensaje pero con un hash (SHA-1) diferente [10, 11].

Copiar rangos de commits

Si necesitas copiar varios commits, puedes especificar un rango utilizando dos puntos sucesivos (..) [12]:

git cherry-pick <commit-A>..<commit-B>

Esto tomará todos los commits posteriores a commit-A, hasta e incluyendo commit-B, y los colocará en tu rama actual [12].
