Sesión 7: Deshacer Cambios y Recuperación

← Volver al Temario Principal

A veces cometemos errores y necesitamos regresar nuestro código a un estado anterior. Git nos ofrece diferentes comandos dependiendo de si los cambios han sido confirmados (commits) o si solo están en nuestro directorio de trabajo.

Restaurar archivos del directorio de trabajo

Si has modificado un archivo pero aún no lo has preparado ni confirmado, y quieres descartar esos cambios para devolverlo a como estaba en el último commit, puedes usar:

git checkout -- archivo.txt

También puedes usar git checkout -- . para deshacer todos los cambios en el directorio de trabajo recursivamente [1].

Retornar a estados anteriores (git reset)

  • Soft Reset: Si quieres deshacer el último commit pero mantener los cambios en tus archivos (por ejemplo, para agruparlos o modificarlos), usa la bandera --soft [2]:
    git reset --soft HEAD~
  • Hard Reset: Si quieres descartar permanentemente el último commit y eliminar también todos los cambios que contenía de tu directorio de trabajo [2]:
    git reset --hard HEAD~
⚠️ Cuidado: Mientras que un commit descartado puede recuperarse con el reflog, los cambios no confirmados que elimines con --hard se perderán para siempre [1].

Utilizar git reset en commits que ya has subido (pushed) a un servidor remoto (como GitHub) altera el historial y desincronizará a tu equipo. ¡Nunca debes reescribir el historial público! [3]. Para estos casos, usamos git revert.

Cómo funciona git revert

En lugar de "borrar" un commit del historial, git revert toma los cambios introducidos por un commit específico y crea un nuevo commit "contra-commit" que deshace sus efectos de forma segura [4].

Ejemplo de uso

Si acabas de subir un commit que contiene un error y necesitas deshacerlo rápidamente:

git revert HEAD~1
git push

Si el commit que deseas revertir está más atrás en el historial, simplemente pasa el hash (SHA-1) del commit [4]:

git revert 912aaf0228338d0c8fb8cca0a064b0161a451fdc

Esto dejará un rastro público claro de que un cambio fue revertido, manteniendo intacto el orden del proyecto para todos tus compañeros [3].

Con Git, casi siempre puedes retroceder el reloj [5]. Git no elimina tus commits "huérfanos" (aquellos que han quedado fuera del historial tras un reset, eliminación de rama o un rebase fallido) durante al menos 90 días por defecto [5, 6].

Cómo usar git reflog

El comando reflog mantiene un historial de cada movimiento que ha hecho tu puntero HEAD en tu máquina local [6].

git reflog

La salida te mostrará algo como esto [6]:

4a5cbb3 HEAD@{0}: rebase finished: returning to refs/heads/foo
904f7f0 HEAD@{2}: rebase: checkout upstream/master
3cbe20a HEAD@{3}: commit: fixed such and such

Recuperando el trabajo perdido

Si por error hiciste un git reset --hard o arruinaste un rebase, simplemente busca en el reflog el punto justo antes de que cometieras el error (por ejemplo, HEAD@{3}) y ejecuta [7]:

git reset --hard HEAD@{3}

O usando el hash específico que el reflog te mostró [8]:

git reset --hard <sha1-of-commit>

¡Y listo! Tu código y tu historial habrán regresado exactamente a como estaban en ese momento [7].
