Sesión 8: Rebase y Squashing

← Volver al Temario Principal

El comando git rebase te permite "reaplicar" una serie de commits encima de otro commit diferente [1]. En la práctica, esto sirve para mantener un historial lineal y limpio, integrando los últimos cambios sin crear un commit de fusión (merge).

Cómo hacer un Rebase Local

Para hacer un rebase de tu rama actual (por ejemplo, una rama topic) sobre la rama master, primero cambias a tu rama y luego ejecutas el comando [1]:

git checkout topic
git rebase master

Alternativamente, puedes hacerlo en un solo paso con [1]:

git rebase master topic
⚠️ Importante: Después de un rebase, los commits aplicados tendrán un hash SHA-1 completamente diferente [1]. Nunca debes hacer rebase de commits que ya hayas empujado (pushed) a un repositorio remoto público, ya que podrías romper el historial de otros colaboradores y te verías obligado a forzar la subida con git push --force [1].

El rebase interactivo permite alterar, reordenar, dividir o combinar (squash) commits en el historial de forma manual antes de que se vuelvan a aplicar [2]. Se inicia añadiendo la bandera -i (interactive) [2].

Iniciando un Rebase Interactivo

Si deseas reorganizar tus últimos 3 commits, ejecutarás [3]:

git rebase -i HEAD~3

Esto abrirá tu editor de texto predeterminado con una lista de commits y comandos disponibles [3]. Por defecto, todos los commits están marcados con pick [3].

Comandos interactivos comunes

  • pick (p): Usar este commit tal cual [4]. Para cambiar el orden de los commits, simplemente cambia el orden de las líneas en el editor [3].
  • reword (r): Usa el commit, pero detiene el proceso para permitirte editar el mensaje del commit [4].
  • edit (e): Usa el commit, pero detiene el proceso para que modifiques los archivos o dividas el commit en partes más pequeñas [5, 6].
  • Eliminar un commit: Si ya no deseas que un commit forme parte de tu proyecto, simplemente borra esa línea en el editor [7].

Una vez que guardes y cierres el archivo, Git ejecutará las instrucciones paso a paso [3, 8].

El "Squashing" es el proceso de tomar múltiples commits separados y combinarlos en un solo commit cohesivo. Es una excelente estrategia para limpiar el historial antes de integrar una rama de características [9, 10].

Squashing mediante Merge

Si deseas incorporar todos los cambios de una rama y condensarlos en un único commit en tu rama actual en lugar de múltiples commits individuales, puedes usar [11]:

git merge --squash nombre_rama
git commit

Esto prepara todos los cambios en el área de staging, dándote la oportunidad de agruparlos en un nuevo commit unificado [11].

Squashing durante un Rebase Interactivo

Si prefieres limpiar el historial de tu rama actual combinando varios commits anteriores en uno solo, puedes usar el rebase interactivo [11]. En el editor de texto (activado con git rebase -i), cambia la palabra pick por squash (o la letra s) en los commits que desees combinar [12].

pick 08c275d Primer borrador: db.sql
squash 06f81c9 Arreglo en la base de datos
squash 0309336 Actualización de la lógica

El commit marcado con squash se combinará con el commit inmediatamente anterior a él (hacia arriba) [13]. Luego de cerrar el editor, Git te pedirá que edites y confirmes un mensaje unificado para el nuevo commit resultante [14].

Nota: También existe fixup (f), que funciona igual que squash, pero descarta automáticamente el mensaje del commit fusionado [4].
